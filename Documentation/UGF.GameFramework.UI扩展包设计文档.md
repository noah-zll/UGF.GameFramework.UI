## 1. 项目概述

### 1.1 项目定位

**UGF.GameFramework.UI** 是基于 Unity GameFramework 的 UI 扩展包，旨在提供一套高效、规范的 UI 开发工作流。它通过自动化工具和代码生成技术，解决了传统 UI 开发中繁琐的组件绑定和样板代码编写问题，让开发者能够专注于业务逻辑的实现。

主要特性：
- **自动化组件绑定**：通过 `UIComponentBinder` 标记组件，自动生成绑定代码，无需手动 `Find` 或拖拽。
- **分部类代码生成**：将 UI 绑定代码（Generated）与业务逻辑代码（Logic）分离，便于维护和重新生成。
- **增强的 UI 基类**：提供 `UIFormBase`，封装了常用的生命周期管理和配置功能。
- **可视化配置工具**：提供 `UIDesigner` 窗口，统一管理代码生成路径、命名空间等设置。

### 1.2 设计理念

- **非侵入式**：基于 GameFramework 原生 UI 模块扩展，不修改底层源码。
- **约定优于配置**：提供合理的默认设置，同时支持自定义路径和命名空间。
- **逻辑与视图分离**：通过 Partial Class 技术，将自动生成的视图绑定代码与手写的业务逻辑代码物理分离。

### 2.2 核心模块

| 模块 | 类名 | 职责 |
|------|------|------|
| **Runtime Core** | `UIFormBase` | UI 窗体基类，继承自 GF 的 `UIFormLogic`，负责生命周期和组件管理。 |
| **Runtime Component** | `UIComponentBinder` | 挂载在 Prefab 上的标记组件，用于指示代码生成器需要绑定的 UI 元素。 |
| **Runtime Data** | `UIFormConfig` | 序列化配置类，存储窗体的属性（如淡入淡出、优先级、组名等）。 |
| **Editor Tool** | `UIDesignerWindow` | 编辑器窗口，提供全局设置和操作入口。 |
| **Editor Core** | `UICodeGenerator` | 负责解析 Binder 信息并生成 C# 代码。 |

## 3. 核心组件

### 3.1 UIFormBase

扩展自 `UnityGameFramework.Runtime.UIFormLogic`，是所有具体 UI 窗体的基类。

**主要功能：**
- **自动绑定**：在 `OnInit` 阶段调用 `BindComponents`（由生成代码实现）。
- **生命周期封装**：提供 `OnUIFormInit`, `OnUIFormOpen`, `OnUIFormClose` 等虚方法，简化子类实现。
- **配置管理**：持有 `UIFormConfig`，支持运行时访问窗体配置。
- **组件获取**：提供泛型 `GetComponent<T>` 方法。

```csharp
public abstract class UIFormBase : UIFormLogic
{
    // 自动绑定的组件字典
    protected Dictionary<string, Component> BoundComponents { get; }
    
    // 窗体配置
    public UIFormConfig Config { get; }

    // 子类需实现的绑定方法（自动生成）
    protected virtual void BindComponents() { }
}
```

### 3.2 UIComponentBinder

用于在 Unity Editor 中标记需要生成的组件。

**属性：**
- `ComponentTypeName`: 绑定的组件类型（如 `Button`, `Text`, `Image`）。
- `BindEvents`: 是否自动生成事件绑定代码（如 `Button.onClick`）。
- `ComponentPath`: 组件相对于根节点的路径（自动维护）。

### 3.3 UIFormConfig

数据类，定义 UI 窗体的行为属性。

**包含属性：**
- `FormName`: 窗体名称。
- `AssetPath`: 资源路径。
- `UIGroupName`: 所属 UI 组。
- `Priority`: 显示优先级。
- `FadeInDuration` / `FadeOutDuration`: 淡入淡出动画时长。
- `ShowMode`: 显示模式（Normal, Modal, Fullscreen, Popup）。

## 4. 开发工具

### 4.1 UI Designer Window

通过菜单 `UGF -> GameFramework -> UI Designer -> Settings Window` 打开。

**功能设置：**
- **代码生成路径**：
  - `Logic Generate Path`: 业务逻辑代码存放路径。
  - `Binding Generate Path`: 绑定代码存放路径（建议放入 Generated 文件夹）。
- **命名空间**：设置生成的代码默认命名空间。
- **Prefab 设置**：生成 Prefab 的存放路径。
- **高级选项**：是否生成详细注释、是否使用 Region 标记等。

## 5. 工作流

### 步骤 1: 创建 UI 界面
在 Unity 场景中搭建 UI 界面，使用 uGUI 组件。

### 步骤 2: 标记组件
选中需要代码控制的 UI 节点（如按钮、文本框），添加 `UIComponentBinder` 组件。
- 工具会自动识别该节点上的主要 UI 组件类型。
- 勾选 `Bind Events` 可自动生成事件回调（仅限 Button 等交互组件）。

### 步骤 3: 生成代码
通过右键菜单或 `UIDesigner` 工具点击生成。
系统将生成两个文件：
1. `MyForm.Generated.cs`: 包含组件字段声明和绑定逻辑。
2. `MyForm.cs`: 包含业务逻辑模板（仅首次生成，不会覆盖）。

### 步骤 4: 编写业务逻辑
打开 `MyForm.cs`，在 `OnUIFormOpen` 等生命周期方法中编写逻辑。可以直接使用生成的组件字段（如 `m_BtnClose`），无需 `GetComponent`。

## 6. 代码生成系统

### 6.1 绑定代码 (Generated)

文件名示例：`MainMenuForm.Generated.cs`

```csharp
// <auto-generated>
// 此文件由 UIDesigner 自动生成
// </auto-generated>
using UnityEngine;
using UnityEngine.UI;
using UGF.GameFramework.UI;

namespace MyGame.UI
{
    public partial class MainMenuForm : UIFormBase
    {
        [SerializeField] private Button m_BtnStart;
        [SerializeField] private Text m_TxtTitle;

        public Button BtnStart => m_BtnStart;
        public Text TxtTitle => m_TxtTitle;

        protected override void BindComponents()
        {
            base.BindComponents();
            // 自动生成的绑定验证逻辑
            if (m_BtnStart == null) Debug.LogWarning("...");
        }

        private void InitializeEvents()
        {
            m_BtnStart.onClick.AddListener(OnBtnStartClick);
        }

        // 分部方法定义
        partial void OnBtnStartClick();
    }
}
```

### 6.2 业务逻辑代码 (Logic)

文件名示例：`MainMenuForm.cs`

```csharp
using UnityEngine;
using UGF.GameFramework.UI;

namespace MyGame.UI
{
    public partial class MainMenuForm
    {
        protected override void OnUIFormOpen(object userData)
        {
            base.OnUIFormOpen(userData);
            // 直接访问组件
            m_TxtTitle.text = "Hello World";
        }

        // 实现分部方法
        partial void OnBtnStartClick()
        {
            Debug.Log("Start Game!");
        }
    }
}
```

## 7. 配置系统

扩展包使用 `UIFormConfig` ScriptableObject 或序列化数据来管理窗体属性。这允许策划或开发者在 Inspector 中直接调整 UI 的淡入淡出时间、层级和组别，而无需修改代码。

目前配置主要集成在 `UIFormBase` 中，通过序列化字段直接暴露给编辑器。

## 8. 最佳实践

1.  **命名规范**：GameObject 命名建议清晰表达用途，代码生成器会基于 GameObject 名称生成变量名（例如 `BtnSubmit` -> `m_BtnSubmit`）。
2.  **目录管理**：建议将生成的绑定代码 (`.Generated.cs`) 放在单独的目录中，并加入 `.gitignore`（如果希望纯本地生成），或者提交到版本控制但标记为生成文件。
3.  **事件处理**：尽量使用自动生成的事件绑定方法，保持代码风格统一。
4.  **组件复用**：对于复杂的子 UI 模块，可以单独制作 Prefab 并生成对应的逻辑类，然后在主窗体中引用。
